# קופה קיוסק בריכה — מערכת ניהול עסק

מערכת קופה וניהול עסק מקומית: עמדת מכירה, שעון נוכחות, מלאי, הוצאות ושכר. עברית מלאה (RTL), חינם לגמרי, ללא מנויים — הנתונים שלכם נשארים אצלכם.

עכשיו גם **אפליקציית טלפון** (אנדרואיד + אייפון) עם **סנכרון אוטומטי בין כל המכשירים**: מכירה שנרשמת בטלפון של עובד מגיעה לבד למחשב של המנהל, וגיבוי התיקייה במחשב מתעדכן איתה.

| קובץ | מה זה |
|---|---|
| `index.html` | האפליקציה — גרסת עבודה עם PWA וסנכרון |
| `sw.js`, `manifest.webmanifest`, `icons/` | קבצי אפליקציית הטלפון (עבודה ללא אינטרנט, אייקון, התקנה) |

> **אבטחה:** המאגר הזה ציבורי ולכן **אין בו שום סיסמה**. בכניסה הראשונה האפליקציה מבקשת לבחור סיסמת מנהל, והיא נשמרת רק בנתונים שלכם (במכשיר ובמאגר הפרטי). מומלץ לשמור עותק של הגרסה המקורית של האפליקציה בתוך המאגר הפרטי `kupa-data`.

---

## הקמה חד-פעמית (בערך 10 דקות, מהמחשב)

### שלב 1 — הפעלת האתר (GitHub Pages, חינם)
1. במאגר הזה ב-GitHub: **Settings ← Pages**.
2. תחת **Branch** בחרו `main` ותיקייה `/ (root)`, ולחצו **Save**.
3. אחרי כדקה יופיע קישור בסגנון `https://yonatantohar-cell.github.io/businesssystem/` — **זה הקישור של האפליקציה**. שימרו אותו.

> האתר חייב אינטרנט רק בפתיחה הראשונה ובעדכונים. אחרי ההתקנה בטלפון הוא עובד גם בלי אינטרנט בכלל.

### שלב 2 — יצירת מאגר נתונים פרטי (לסנכרון)
הנתונים העסקיים **לא** נשמרים במאגר הזה (שהוא ציבורי) אלא במאגר **פרטי** נפרד בחשבון שלכם:
1. ב-GitHub לחצו **New repository**.
2. שם: למשל `kupa-data`. בחרו **Private**. סמנו **Add a README** (כדי שהמאגר לא יהיה ריק). צרו.

### שלב 3 — יצירת מפתח גישה (Token)
1. ב-GitHub: תמונת הפרופיל ← **Settings** ← בתחתית **Developer settings** ← **Personal access tokens** ← **Fine-grained tokens** ← **Generate new token**.
2. שם: `kupa-sync`. תוקף (Expiration): מומלץ שנה (בסיום התוקף פשוט יוצרים מפתח חדש ומזינים אותו מחדש בכל מכשיר).
3. **Repository access**: בחרו **Only select repositories** ← סמנו את `kupa-data` בלבד.
4. **Permissions ← Repository permissions ← Contents ← Read and write**.
5. צרו והעתיקו את המפתח (`github_pat_...`) — שימרו אותו בצד, הוא מוצג פעם אחת בלבד.

### שלב 4 — חיבור כל מכשיר
בכל מכשיר (המחשב, הטלפון שלכם, טלפון של עובד):
1. פתחו את קישור האפליקציה ← **אזור מנהל** (סיסמת מנהל) ← **הגדרות** ← **סנכרון בין מכשירים**.
2. הזינו: מאגר `yonatantohar-cell/kupa-data` ואת המפתח, ולחצו **שמור והתחבר**.
3. זהו. מעכשיו המכשיר מסונכרן אוטומטית — הצ'יפ "מסונכרן" למעלה מראה את המצב.

> **טיפ:** חברו את הסנכרון בכל מכשיר חדש **לפני** שמתחילים להקליד בו נתונים — כך הוא מאמץ את נתוני הענן הקיימים במקום להתחיל קטלוג כפול.

## התקנה על הטלפון

**אנדרואיד (Chrome):** פתחו את הקישור ← תפריט ⋮ ← **הוספה למסך הבית / התקנת אפליקציה**.

**אייפון (Safari):** פתחו את הקישור ← כפתור השיתוף (הריבוע עם החץ) ← **הוסף למסך הבית**.

מרגע ההתקנה יש אייקון ₪ במסך הבית והאפליקציה נפתחת במסך מלא ועובדת גם ללא אינטרנט.

## איך הסנכרון עובד

- כל מכשיר עובד **מקומית וללא אינטרנט** — קופה, שעון, הכול. שום פעולה לא נחסמת.
- כשיש אינטרנט, המכשיר שולח ומושך שינויים אוטומטית: כ-10 שניות אחרי כל פעולה, כל דקה, ובכל חזרה לאפליקציה.
- השינויים **מתמזגים** ולא נדרסים: כל מכירה/משמרת/הוצאה היא רשומה נפרדת; עריכה אחרונה גוברת; מחיקות מסתנכרנות לכל המכשירים.
- כל היסטוריית הנתונים נשמרת במאגר הפרטי שלכם ב-GitHub — כל סנכרון הוא גם גיבוי עם היסטוריית גרסאות מלאה.
- **גיבוי התיקייה במחשב** ממשיך לעבוד כרגיל: המחשב מושך את נתוני כל המכשירים וכותב אותם לתיקיית הגיבוי שבחרתם.

## אישורי תשלום מ-Grow (אופציונלי)

חיבור חינמי לגמרי שמציג בקופה כל תשלום ברקוד שאושר ב-Grow: מסך "אישורי תשלום" עם לוג רציף, והתראה קופצת (3 שניות, לא לחיצה) בכל מסך.

**שלב א — פריסת הסקריפט (חד-פעמי, ~5 דקות):**
1. היכנסו אל [script.google.com](https://script.google.com) ← **New project**.
2. מחקו את התוכן והדביקו את הקוד מהקובץ [`apps-script/grow-webhook.gs`](apps-script/grow-webhook.gs) שבמאגר הזה.
3. בשורה `const KEY = ...` החליפו את הערך בסיסמת סוד ארוכה שתמציאו (אותיות ומספרים, בלי רווחים). שימרו אותה בצד.
4. **Deploy ← New deployment ← ⚙ ← Web app**. הגדירו: Execute as = **Me**, Who has access = **Anyone**. לחצו Deploy ואשרו את ההרשאות.
5. העתיקו את כתובת ה-Web app (מסתיימת ב-`/exec`) — זו הכתובת שלכם.

**שלב ב — בלוח הבקרה של Grow:** הגדירו Webhook על עסקה מוצלחת אל:
`<כתובת ה-exec שלכם>?key=<הסוד שבחרתם>`

**שלב ג — באפליקציה:** אזור מנהל ← הגדרות ← **אישורי תשלום (Grow)** ← הדביקו כתובת + מפתח ← שמור ← "בדיקת חיבור". ההגדרה מסתנכרנת לכל המכשירים.

**עדכון הסקריפט בעתיד:** אחרי שינוי קוד — **שמרו** (Ctrl+S), ואז Deploy ← **Manage deployments** ← ✎ (עריכה של הפריסה הקיימת, לא "New deployment") ← Version: **New version** ← Deploy. כך הכתובת נשארת זהה.

> **בדיקה שהפריסה אכן התעדכנה:** פתחו בדפדפן את `<כתובת ה-exec>?action=ping`. תשובה תקינה: `{"ok":true,"version":4}`. אם מופיע `{"ok":false,"error":"bad key"}` — הכתובת עדיין מגישה את הקוד הישן: ודאו ששמרתם, ושעדכנתם את **אותה** פריסה שכתובתה מוגדרת באפליקציה (השוו את מזהה ה-`/s/XXXX/` בכתובות).

הערות: הסקריפט שומר את הלוג גם בגיליון Google Sheets בשם "Grow Payments Log" בדרייב שלכם (בונוס: יומן ביקורת). ההתראות והלוג הם תיעוד בלבד — המכירה עצמה נרשמת בקופה כרגיל. מי שמחזיק את כתובת ה-exec **ואת המפתח** יכול לקרוא את הלוג; שמרו על המפתח כמו על סיסמה.

## תפריט דיגיטלי והזמנה עצמית — Incanto (אופציונלי)

לקוחות סורקים QR, רואים תפריט עם תמונות, מזמינים ומשלמים מהטלפון — וההזמנה קופצת במסך "הזמנות" בקופה. הכול על אותה תשתית חינמית (GitHub Pages + Apps Script).

**דרישה מוקדמת:** חיבור Grow/Apps Script פעיל (הפרק הקודם), עם **הגרסה המעודכנת** של `apps-script/grow-webhook.gs` (היא כוללת גם את התפריט וההזמנות; אחרי עדכון הקוד — Deploy ← Manage deployments ← ✎ ← New version).

**בניית התפריט (מנהל):** אזור מנהל ← **תפריט דיגיטלי** ← מוסיפים מנות (שם, קטגוריה, מחיר, תיאור, תמונה — נדחסת אוטומטית) ← **פרסום התפריט**. שינויים הם טיוטה עד הפרסום.

**הקישור ללקוחות:** מופיע באותו מסך ("קישור ללקוחות"). הפיקו ממנו קוד QR (כל מחולל QR חינמי) והדביקו על השולחנות/הדלפק.

**שתי דרכי תשלום ללקוח:**
- **תשלום מקוון (Morning):** הדביקו בשדה "קישור תשלום מקוון" את קישור התשלום שלכם (למשל `https://mrng.to/XXXXXXXX`). דף התשלום נפתח בתוך האפליקציה עם מילוי אוטומטי של סכום, מספר הזמנה, שם וטלפון לפי תבנית הפרמטרים שבשדה שמתחתיו. אחרי התשלום הלקוח לוחץ "סיימתי לשלם", ההזמנה מסומנת כשולמה ועוברת אוטומטית ל"בהכנה".
- **תשלום בקופה:** ההזמנה נשלחת מיד למטבח ומופיעה בקופה כ"ממתינה לתשלום" עם כפתור **₪ שולם** — לחיצה עליו מסמנת תשלום ומעבירה ל"בהכנה".

> **מגבלה שכדאי להכיר:** Morning לא שולח Webhook למערכת, ולכן אישור התשלום המקוון מבוסס על לחיצת הלקוח. הסכום תמיד ניתן לאימות בלוח הבקרה של Morning. כמו כן ייתכן שקישור מקוצר (mrng.to) לא יעביר את הפרמטרים — במקרה כזה השתמשו בקישור המלא של דף התשלום, או השאירו את שדה הפרמטרים ריק והלקוח ימלא ידנית.

**מסך "הזמנות" בקופה:** כל הזמנה חדשה קופצת עם התראה; לוחצים כדי לקדם סטטוס (חדשה ← בהכנה ← מוכנה ← נמסרה). הסטטוסים מסתנכרנים בין כל המכשירים.

הערות: התפריט הוא מידע ציבורי (כמו כל תפריט); ההזמנות נשלחות לנקודת קצה ציבורית — מספר ההזמנה בלבד חשוף ללקוח, והפרטים המלאים דורשים את המפתח. אם דף התשלום של Grow מסרב להיפתח בתוך מסגרת (תלוי בהגדרות החשבון ב-Grow), הלקוח יקבל כפתור לפתיחתו בחלון נפרד והאישור עדיין יופיע אוטומטית.

### גיבוי ידני בטלפון
בטלפון אין חיבור תיקייה, ולכן כפתורי הגיבוי משתפים קובץ: **גיבוי.json** (לשחזור מלא) ו-**דוח.csv** (דוח קריא) דרך וואטסאפ / דרייב / מייל. שחזור: הגדרות ← "טען מקובץ גיבוי".

### דברים שכדאי לדעת
- **מלאי בשתי קופות בו-זמנית:** אם שני מכשירים מוכרים את אותו מוצר באותו רגע, ספירת המלאי עלולה לסטות מעט (המכירות עצמן נשמרות תמיד במלואן). אפשר לתקן מלאי בכל רגע ב"מלאי ומוצרים".
- **המפתח = גישה לנתונים:** מי שמחזיק את המפתח יכול טכנית לקרוא את מאגר הנתונים. מסרו אותו רק למכשירים שאתם סומכים עליהם; סיסמת המנהל עדיין חוסמת את אזור המנהל באפליקציה. אפשר לבטל מפתח בכל רגע ב-GitHub (Developer settings ← Tokens).
- **"מחיקת כל הנתונים"** בהגדרות מוחקת בכל המכשירים המסונכרנים (זו הכוונה — מחיקה אמיתית).
- פג תוקף המפתח? הצ'יפ יציג "שגיאת סנכרון" — צרו מפתח חדש והזינו אותו מחדש בכל מכשיר.
